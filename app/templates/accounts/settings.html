Architecture

Listener Service captures events from Telegram and publishes them to RabbitMQ.

Event Worker processes queued events, handling user tracking, message archiving, and download scheduling.

This decoupling ensures no events are lost even under high load.

Raw Events

When enabled, raw event JSON is stored before processing and linked to the resulting archived message.

Access raw events via Django Admin under Events > Raw Events.

About Exclusions

Global exclusions prevent real-time messages from being processed for the specified user across all sources.

Source exclusions prevent real-time messages from being processed from the selected sources.

User profiles are still updated when excluded users post.

If you need to stop all posts from a specific source being processed, use the "bypass listener" feature on the sources' config page.

About Notifications

Notitications send a webhook or RabbitMQ message whenever a watched entity (URL, hashtag, @mention, domain, etc.) is observed in a Telegram message.

Every occurrence: fires every time the watched (entity type, value) pair appears in a new message.

New occurrence: fires once total, the first time the pair is matched. After that the rule goes silent until you reset it.

Targets can be a webhook (HTTP POST with optional HMAC) or a RabbitMQ queue you control.

Security
  • Private (10.x / 172.16-31.x / 192.168.x) and loopback targets are allowed for self-hosted webhooks. Link-local and cloud-metadata addresses are blocked.
  • If a secret is set, payloads carry an HMAC-SHA256 signature in X-Trawlr-Signature.
  • Failed deliveries are retried on a 15s / 30s / 60s / 5m / 1h schedule.
